# Identity & Access コンテキスト — 設計判断

## 概要

認証・認可を担うコンテキスト。他のコンテキストとは異なり、**ステートレスな設計**を採用している。

## 他コンテキストとの構成差異

| 項目 | 他コンテキスト | Identity & Access |
|---|---|---|
| 集約 | あり（DB永続化） | なし（ステートレス） |
| ドメインイベント | あり | なし |
| DBテーブル | あり | なし |
| 永続化 | JPA + PostgreSQL | JWT（ステートレストークン） |

## 設計判断の理由

1. **管理者は1人のみ** — パスワードは環境変数で管理すれば十分。DB に保存する必要がない
2. **参加者認証はイベントの JoinCode で行う** — Event コンテキストが JoinCode を管理しており、Identity は検証のみ
3. **セッション状態を持たない** — JWT にロール・eventId を含めることで、サーバー側にセッションストアが不要
4. **将来の拡張性** — 複数管理者やOAuth対応が必要になった場合は、このコンテキストに集約を追加する
